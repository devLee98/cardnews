# `back/inventory.py` — 데이터를 AI가 볼 수 있는 크기로 줄이는 곳

> **한 줄 요약**
> 업로드한 공구 JSON은 수십만 자라 AI에게 그대로 보낼 수 없습니다.
> 이 파일이 필요한 만큼만 잘라내서 프롬프트에 들어갈 크기로 만듭니다.

---

## 1. 왜 필요한가요

이 파일에 들어오는 데이터는 **공구 한 건**입니다. 업로드 파일에 공구가 여러 건 있어도 화면에서 하나만 골라 보내기 때문입니다. (→ [05번 문서](05-controller.md))
그래서 `events`는 항상 `1/1`로 나옵니다.

공구 한 건에도 이런 게 다 들어 있습니다.

- 상품 15종의 모든 정보
- 상품마다 리뷰 수십 개 (본문 전체)
- 상세페이지 이미지 주소 수십 개
- 인스타 포스트 캡션
- 큐레이터 정보, 브랜드 정보

이걸 다 합치면 **수십만 자**가 됩니다. AI가 한 번에 읽을 수 있는 양을 훌쩍 넘습니다.
보낸다 해도 비용이 크고, 무엇보다 **중요한 정보가 잡다한 정보에 묻힙니다.**

그래서 단계마다 필요한 만큼만 잘라서 보냅니다.

| 단계 | 무엇을 보내나 | 왜 |
|---|---|---|
| ① 구성안 | **값이 아니라 목록** — "어떤 데이터가 얼마나 채워져 있는지" 표 | 몇 장을 만들지 정하는 데는 실제 값이 필요 없습니다 |
| ③ 문구 | **실제 값** — 단, 구성안이 쓰겠다고 지목한 경로만 | 문구를 쓰려면 진짜 값이 필요합니다 |

## 2. 경로 표기법 — 이 파일의 핵심 아이디어

### 문제: 이름이 겹칩니다

실제 데이터에는 이런 값들이 있습니다.

- 브랜드의 `name` (브랜드명)
- 상품의 `name` (제품명)

이름만 세면 둘이 한 줄로 합쳐져서 **어느 쪽 데이터인지 알 수 없게 됩니다.**

### 해결: 전체 경로를 씁니다

```
events[].brand.name         ← 브랜드명
events[].products[].name    ← 제품명
```

### 배열은 `[]` 로 합칩니다

상품이 15개라고 해서 15줄을 만들지 않습니다.

```
❌ 이렇게 하면 표가 수백 줄이 됩니다
events[0].products[0].name
events[0].products[1].name
events[0].products[2].name
...

✅ 이렇게 한 줄로 모읍니다
events[].products[].name
```

> ⚠️ **중요**: 이 표기법은 `card_spec.py`(카드 단계 명세)의 데이터 이름 표기와 **정확히 같아야 합니다.**
> 하나라도 어긋나면 "데이터가 없다"고 잘못 판단해서 카드가 통째로 빠집니다.

## 3. `build_inventory` — 어떤 데이터가 얼마나 있는지 세기

JSON 전체를 재귀적으로 훑으면서 경로마다 4가지를 셉니다.

| 세는 것 | 뜻 | 예시 |
|---|---|---|
| **occurrences (나오는 자리)** | 그 경로가 등장하는 총 횟수 | 상품이 6개면 `products[].name`은 6 |
| **filled (채움)** | 그중 값이 실제로 들어 있는 자리 수 | 3개 상품에만 리뷰가 있으면 3 |
| **items (항목수)** | 배열이면 전체 길이의 합 | 리뷰가 총 47개면 47 |
| **samples (예시)** | 값이 어떻게 생겼는지 맛보기 | "하루비타 유산균 3종" |

### "채움"을 `3/6` 처럼 읽는 이유

`filled / occurrences` 로 표시합니다. 상품 6종 중 3종에만 리뷰가 있다면 `3/6` 입니다.

**이 숫자가 AI의 판단 근거입니다.**
- `0/6` → 이 데이터는 없는 것으로 봅니다. 필수 데이터가 이 상태면 그 카드를 안 만듭니다.
- `6/6` → 충분히 있으니 마음 놓고 씁니다.

### 값이 "비어 있다"의 기준

다음 중 하나면 비어 있는 것으로 봅니다.

- 값이 없음 (`null`)
- 빈 문자열이거나 공백만 있음
- 빈 배열 `[]` 또는 빈 객체 `{}`

> 💡 숫자 `0`이나 `false`는 **비어 있는 게 아닙니다.** 할인율 0%도 엄연한 값이기 때문입니다.

## 4. 예시(samples)를 만드는 규칙

AI가 "이 데이터가 어떻게 생겼는지" 감을 잡으려면 맛보기가 필요합니다. 하지만 다 보여주면 표가 터집니다.

### 규칙 1 — 최대 3개까지만

```
events[].products[].name | 6/6 | - | 주방세제 3종 / 핸드워시 세트 / 욕조클리너
```

**왜 3개인가?** 1개만 보여주면 "주방세제 공구"라고만 알고, 실제로는 여러 제품군이 섞인 공구인 걸 놓칩니다.
3개를 보여주면 *"주방세제·핸드워시 등"* 처럼 실제 내용을 아는 설명을 쓸 수 있습니다.

### 규칙 2 — 첫 예시가 길면 하나로 충분

첫 번째 예시가 40자를 넘으면(큐레이터 피치나 리뷰 본문 같은 긴 문장) 더 모으지 않습니다.
긴 문장을 3개 보여줘 봐야 표만 길어지고 얻는 게 없습니다.

### 규칙 3 — 한 개당 80자까지, 넘으면 잘라냅니다

```
events[].products[].curator_pitch | 6/6 | - | 제가 3개월 동안 직접 써보고 진짜 좋아서 소개하는 제품인데요, 아침마다…
```

### 규칙 4 — 구조체는 예시를 남기지 않습니다

리뷰 배열처럼 안에 또 객체가 들어 있는 값은 예시를 만들지 않고 `-` 로 둡니다.
대신 **항목수**로 몇 개인지만 알려줍니다.

### 규칙 5 — 표 전체는 최대 200줄

경로가 아무리 많아도 200개까지만 보여줍니다.

### 규칙 6 — 맨 바깥 `meta` 는 아예 세지 않습니다

`meta` 는 **파일에 대한 설명이지 공구에 대한 설명이 아닙니다.**
생성 시각, 원본 파일명, sha256 해시, 전체 집계 같은 것들이 들어 있습니다.

**빼는 가장 큰 이유는 숫자가 틀리기 때문입니다.**

화면은 공구가 여러 건인 파일에서 **하나만 남겨** 보냅니다 (`pickEvent`).
그런데 자르는 건 `events` 뿐이고 `meta` 는 그대로 따라옵니다.

```
실제로 보낸 것   상품 16개 / 이벤트 1개
meta 가 말하는 것  상품 154개 / 이벤트 8개
```

AI 가 이 값을 그대로 믿으면 **"154종"** 같은 문구가 나옵니다.

나머지 두 가지 이유도 있습니다.

- **자리를 많이 차지합니다.** 경로 95개 중 23개(24%)가 `meta` 였습니다.
- **읽는 법을 설명하는 산문이 들어 있습니다.** `meta.comparison_usage` 가
  "각 상품의 comparison_rows를 바로 읽습니다…" 라고 안내하는데,
  그 경로는 규칙 7에서 이미 빠져 있습니다. **없는 경로를 읽으라고 말하는 셈**입니다.

빼고 나면 95개 → **72개**로 줄고, 카드 단계 명세가 쓰는 경로는 하나도 빠지지 않습니다.

> 💡 **맨 바깥의 `meta` 만 막습니다.** `events[].meta` 처럼 안쪽에 있는 것은 그대로 둡니다.
> 공구에 딸린 값일 수 있어서, 이름만 같다고 같이 버리면 안 됩니다.

### 규칙 7 — 비교표 세 필드는 아예 세지 않습니다

`comparison_status` / `comparison_info` / `comparison_rows` 는 경로를 세지도,
값을 뽑지도 않습니다. `back/comparison.py` 가 따로 걸러서 문구 단계에 직접 넘깁니다.
(→ [06번 문서](06-comparison.md))

**왜 빼야 했나.** 이 셋을 그냥 두면 경로가 **249개 늘어납니다.**
`values` 와 `product_notes` 가 경쟁사 제품명을 Key 로 쓰기 때문에,
상품 하나마다 `…comparison_rows[].values.프랭클린 비건 아기주방세제 500ml…` 같은
새 경로가 생기는 탓입니다. 그래서 두 가지가 한꺼번에 터집니다.

1. **정작 필요한 경로가 잘려 나갑니다.** 전체 경로가 344개가 되어 규칙 5의 200줄 상한에
   걸리는데, 정렬이 경로 순이라 `comparison_*` 이 `consumer_price`·`name`·`reviews` 보다
   앞에 옵니다. 가격도 상품명도 없는 표가 AI에게 전달됩니다.
2. **경로 자체에 경쟁사 제품명이 박혀 있습니다.** 표에 싣는 것만으로 이름이 노출됩니다.

빼고 나면 344개 → **106개**로 줄고, 카드 단계 명세가 쓰는 경로는 하나도 빠지지 않습니다.

`extract_values` 에도 같은 차단이 걸려 있습니다. 구성안이 실수로 비교표 경로를 적어 와도
값을 뽑지 않습니다. 걸러내지 않은 원본이라 경쟁사 이름과 단품 가격이 그대로 들어 있습니다.

## 5. 실제로 만들어지는 표

```
경로 | 채움 | 항목수 | 예시
events[].brand.name | 1/1 | - | 프랭클린
events[].curator.nickname | 1/1 | - | 차차맘
events[].event_name | 1/1 | - | 프랭클린 생활세제 공구
events[].products[].base_sale_price | 6/6 | - | 22900 / 18200 / 31900
events[].products[].certifications | 0/6 | - | -
events[].products[].detail_image_urls | 6/6 | 48 | https://…/detail_01.jpg
events[].products[].name | 6/6 | - | 주방세제 3종 / 핸드워시 세트 / 욕조클리너
events[].products[].reviews | 3/6 | 47 | -
events[].reservation.add_count | 1/1 | - | 9382
```

경로 순(알파벳순)으로 정렬해서, 구조를 따라 읽히게 합니다.

이 표가 그대로 ①번 구성안 프롬프트에 들어갑니다.

## 6. `empty_paths` — 전부 비어 있는 경로 목록

`0/6` 처럼 **나오는 자리마다 전부 비어 있는** 경로만 따로 뽑습니다.

이 목록은 두 곳에서 쓰입니다.

1. **프롬프트에 다시 강조해서 붙입니다.** 표에 이미 `0/6`으로 나와 있지만, 한 번 더 명시해야 AI가 확실히 인지합니다.
   ```
   ## 값이 전부 비어 있는 경로
   events[].products[].certifications, events[].social_posts[].caption
   이 경로들은 데이터가 없는 것으로 보고 판단한다.
   ```
2. **화면에 표시합니다.** 관리자가 "아, 이 공구는 인증 정보가 없구나"를 알 수 있게 합니다.

## 7. `extract_values` — 실제 값 뽑아내기 (③번 문구 단계용)

구성안이 확정되면, **카드마다 "쓰겠다"고 지목한 경로**가 정해집니다.
그 경로들의 실제 값만 뽑습니다.

### 잘라내는 기준

| 기준 | 값 | 이유 |
|---|---|---|
| 경로당 최대 개수 | **6개** | 상품이 15개여도 6개면 톤을 파악하기 충분합니다 |
| 문자열 최대 길이 | **600자** | 리뷰 본문 하나가 수천 자인 경우가 있습니다 |

### 🔑 중복 제거 — 이게 없으면 뒤쪽 상품이 통째로 잘립니다

같은 문구가 여러 상품에 반복되는 일이 아주 흔합니다.
브랜드가 상품 설명을 복사·붙여넣기 하는 경우가 많기 때문입니다.

중복을 안 지우면 이런 일이 생깁니다.

```
❌ 중복 제거 없음 — 6칸이 전부 같은 값으로 채워짐
"셀링포인트": [
  "천연 유래 성분 99%",
  "천연 유래 성분 99%",
  "천연 유래 성분 99%",
  "천연 유래 성분 99%",
  "천연 유래 성분 99%",
  "천연 유래 성분 99%"
]
→ 뒤쪽 상품의 고유한 셀링포인트는 자리가 없어 잘려나감
```

```
✅ 중복 제거 후
"셀링포인트": [
  "천연 유래 성분 99%",
  "손이 트지 않는 순한 처방",
  "욕실 곰팡이까지 한 번에",
  ...
]
```

### ⚠️ 그 중복 제거가 만든 함정 — `extract_product_rows`

경로마다 **따로** 중복을 걸러내다 보니, 목록의 길이가 서로 달라집니다.

```
name               ['주방세제', '바스앤샴푸', '엉덩이클렌저', '핸드워시', '욕조클리너']   ← 5개
naver_rating       [4.92, 4.94, 4.91, 4.95]                                  ← 4개
naver_review_count [9382, 7171, 8897, 10053, 849, 5953]                      ← 6개
```

**몇 번째끼리 짝인지 알 수 없습니다.** 그런데 AI는 자리를 보고 짝지을 수밖에 없습니다.
실제로 `핸드워시 후기 10,053건이 모여 4.95점이에요` 라는 문구가 나왔습니다.
세 값이 전부 다른 상품 것이고, 진짜 핸드워시는 **3,598건 / 4.92점** 입니다.

그래서 상품 단위 값은 **상품별로 묶어서** 따로 보냅니다. 한 줄이 상품 하나입니다.

```json
[
  {"name": "주방세제", "option1": "주방세제 본품 3개",
   "base_sale_price": 22900, "lowest_price": 27300,
   "naver_rating": 4.92, "naver_review_count": 9382},
  ...
]
```

`split_product_paths` 가 묶을 수 있는 경로만 골라냅니다. 셋은 빠집니다.

| 빠지는 것 | 이유 |
|---|---|
| `reviews[].body` | 상품 하나에 여러 개 (경로에 `[]` 가 더 붙음) |
| `detail_image_urls` | 값 자체가 목록이라 한 칸에 안 들어감 |
| `curator_pitch`, `selling_point`, `usp` | 긴 글 (40자 초과) |

긴 글을 빼는 건 **이 표에는 중복 제거가 없기 때문**입니다. 구성이 4개면 같은 피치가
글자 그대로 4번 실려서(6,245자 → 2,391자) 정작 짝지어야 할 숫자가 묻힙니다.
긴 글은 어느 상품 것인지 헷갈릴 일도 없으니 원래 자리에 그대로 둡니다.

> 💡 상품이 최대 **44개**인 공구가 있어서 `MAX_PRODUCT_ROWS`(12줄)로 끊습니다.

## 8. `find_image_urls` — 이미지 생성에 참고할 사진 주소 뽑기

④번 이미지 생성 단계에서, 브랜드 실사를 참고로 넣기 위해 주소를 뽑습니다.

### 받아들이는 조건

- `http` 로 시작해야 함
- 확장자가 `.png` `.jpg` `.jpeg` `.webp` `.gif` 중 하나여야 함
  *(주소 뒤에 `?` 파라미터가 붙어 있으면 잘라내고 확인합니다)*
- 중복 제거

### gif도 받는 이유

움직이는 이미지는 이미지 편집 API가 받지 않습니다.
하지만 **첫 프레임만 뽑아서 정지 이미지로 만들면** 참고 자료로 쓸 수 있습니다.
그래서 일단 받아두고 나중에 변환합니다. (변환은 `04-assets.md` 참고)

## 9. 이 파일을 고칠 일이 있다면

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| AI에게 더 많은 예시를 보여주고 싶다 | `MAX_SAMPLES` (현재 3) |
| 긴 문장도 여러 개 보고 싶다 | `SHORT_VALUE_LENGTH` (현재 40) |
| 표를 더 길게 보여주고 싶다 | `MAX_PATHS` (현재 200) |
| 문구 단계에서 더 많은 상품 값을 보여주고 싶다 | `EXTRACT_MAX_ITEMS` (현재 6) |
