# `back/controller/cardnews.py` — AI를 부르고, 답을 손보는 곳

> **한 줄 요약**
> 실제로 AI를 호출하는 파일입니다. 그리고 **AI가 규칙을 어겼을 때 강제로 바로잡습니다.**
> 여기 있는 규칙은 프롬프트를 아무리 고쳐도 바뀌지 않습니다.

---

## 1. 왜 "덮어쓰기"가 필요한가요

프롬프트로 아무리 정중히 부탁해도 AI는 가끔 규칙을 어깁니다.
어겼을 때 그냥 통과시키면 **관리자가 매번 손으로 고쳐야 합니다.**

그래서 절대 어기면 안 되는 것들은 코드로 강제합니다.

> 💡 반대로 말하면, **여기 있는 규칙을 바꾸려면 프롬프트가 아니라 이 파일을 고쳐야 합니다.**
> "프롬프트를 바꿨는데 결과가 안 변해요" 하는 경우, 대부분 이 파일에서 덮어쓰고 있는 것입니다.

## 2. 전체 흐름

```
[사용자] JSON 파일 업로드          ← 한 파일에 공구가 여러 건(최대 5건)
    ↓
[사용자] 만들 공구 하나 고르기      ← 공구가 한 건뿐이면 자동으로 넘어감
    │                                고른 공구 1건만 서버로 나간다
    ├──────────────┬──────────────┐
    ↓              ↓              │  ← 동시에 실행
① 구성안 생성   ② 이미지 검수      │
  /plan          /assets          │
    │              │              │
    ↓              ↓              │
 카드 목록      쓸 만한 사진 목록  │
    │              │
    │              └→ [사용자] 움짤 직접 고르기
    │              │
    └──────┬───────┘
           ↓
    [사용자] 추가 지시 입력 (선택) → "AI 생성하기" 버튼
           ↓
    ③ 문구 + 디자인 생성  /draft   ← 한 번에 전부
           ↓
    화면에 문구가 먼저 뜸
           ↓
    ④ 이미지 생성  /image        ← 카드마다 1번씩, 동시에 3장까지
           ↓
    카드가 만들어지는 대로 한 장씩 채워짐
```

**공구를 먼저 고르는 이유**: 카드뉴스는 공구 한 건을 소개하는 물건입니다. 여러 건을 한꺼번에 넣으면 어느 공구 이야기인지 알 수 없는 카드가 나옵니다.
**①과 ②를 동시에 돌리는 이유**: 서로 결과가 필요 없어서 기다릴 이유가 없습니다.
**③을 한 번에 부르는 이유**: 카드끼리 흐름이 이어지고 같은 말이 겹치지 않으려면 AI가 전체를 한눈에 봐야 합니다.
**④를 나눠 부르는 이유**: 이미지 한 장에 30~60초가 걸립니다. 8장을 한 번에 요청하면 응답 시간이 초과됩니다.

## 3. 사용하는 모델과 설정

| 설정 | 기본값 | 설명 |
|---|---|---|
| 텍스트 모델 | `gpt-5` | ①②③번에서 사용 |
| 추론 강도 | `low` | ①구성안·②이미지검수 |
| **추론 강도 (문구)** | `medium` | ③문구·디자인 **— 여기만 따로 높입니다** |
| 이미지 모델 | `gpt-image-2` | ④번에서 사용 |
| 이미지 화질 | *(모델 기본값)* | `high` 로 올려 봤다가 되돌림 — 아래 참고 |
| 참조 충실도 | *(꺼짐)* | `gpt-image-1` 계열 전용 — 아래 참고 |
| 이미지 형식 | `png` | 화면에서 그대로 내려받을 수 있게 고정 (코드 상수) |

화질·충실도·모델은 `back/.env` 파일에서 바꿀 수 있습니다.

```
OPENAI_IMAGE_QUALITY=          # 비워 두면 모델이 알아서 판단
OPENAI_INPUT_FIDELITY=         # 비워 둔다. gpt-image-2 에서는 켜면 안 된다
```

### ⚠️ 화질을 `high` 로 올렸다가 되돌린 이유

한 장당 생성 시간이 눈에 띄게 늘어 **카드 8장 전체가 두 배 가까이** 걸렸습니다. 화질 차이는 그만큼 크지 않았습니다.

프론트가 3장씩 나눠 부르기 때문에 한 장이 두 배가 되면 전체도 두 배가 됩니다.

```
한 장 45초 → 3묶음 × 45초 ≈ 2분 15초
한 장 90초 → 3묶음 × 90초 ≈ 4분 30초
```

> 💡 다시 올려 볼 생각이라면 **한 장당 시간을 먼저 재세요.**
> 배포 nginx 응답 제한이 120초라, 한 장이 그걸 넘기면 그 카드는 502로 실패합니다.
> 로컬에는 nginx 가 없어서 아무리 오래 걸려도 성공한 것처럼 보입니다.

### ⚠️ `input_fidelity` 는 지금 모델에서 못 씁니다

참고 사진을 얼마나 그대로 따라갈지 정하는 옵션인데, **`gpt-image-1` 계열에만 있습니다.**
`gpt-image-2` 에 넘기면 카드가 통째로 실패합니다.

```
400 - The model 'gpt-image-2' does not support the 'input_fidelity' parameter.
```

SDK 함수에는 이 파라미터가 있어서 넘길 수는 있지만, **모델이 받는지는 별개입니다.**
그래서 기본값을 비워 두고, `gpt-image-1` 로 내려 쓸 때만 켭니다.

> ⚠️ 화질을 올리면 **한 장당 시간과 비용이 늘어납니다.** 카드 8장이면 8번 곱해집니다.
> 배포 nginx 응답 제한은 120초(`deploy/nginx/cardnews.conf`)라 아직 여유가 있지만,
> 더 올릴 생각이라면 그 값도 함께 봐야 합니다.

> ⚠️ 이미지 형식은 **두 곳이 맞물려 있습니다.** API 에 넘기는 `output_format` 과
> 응답을 감싸는 `data:image/…` 접두사가 어긋나면 화면에서 이미지가 깨집니다.
> 그래서 `IMAGE_FORMAT` 상수 하나로 묶어 뒀습니다.

### 추론 강도 — 단계마다 다릅니다

`gpt-5` 계열은 답하기 전에 **속으로 먼저 생각하는 시간**을 갖습니다. 그 시간을 조절하는 값입니다.

| 단계 | 값 | 왜 |
|---|---|---|
| ① 구성안 | `low` | 10단계 중 고르는 일이라 오래 생각시켜도 결과가 거의 같았습니다 |
| ② 이미지 검수 | `low` | 사진을 한 장씩 분류하는 일에 가깝습니다 |
| ③ 문구·디자인 | **`medium`** | 카드 8장을 한 번에 쓰면서 **서로 말이 겹치지 않게**, 22/60자를 지키고, 가격 세 종류를 헷갈리지 않아야 합니다 |

**전부 올리지 않고 ③만 올린 이유**: 세 호출 중 생각이 실제로 필요한 곳은 ③뿐입니다. 다 올리면 사진 분류(②)까지 같이 느려져서 **기다리는 시간만 늘어납니다.**

```
OPENAI_REASONING_EFFORT=low             # ①②
OPENAI_DRAFT_REASONING_EFFORT=medium    # ③
```

> ⚠️ 원래는 셋 다 `low` 였습니다. 배포 nginx 응답 제한이 **60초**여서 `medium`(50초 이상)이 걸렸기 때문입니다.
> 지금은 [nginx 가 120초](../deploy/nginx/cardnews.conf)로 올라가 있어 여유가 생겼습니다.
> 더 올릴 생각이면 그 값을 먼저 확인하세요.

> 💡 문구 품질이 여전히 아쉽다면 다음 조정 지점은 **텍스트 모델**입니다.
> 다만 `pro` 계열은 훨씬 느려서 120초를 넘길 위험이 있습니다.

## 4. ① 구성안 만들기 (`/cardnews/plan`)

### 하는 일

1. 업로드된 JSON을 훑어서 "어떤 데이터가 얼마나 있는지" 표를 만듭니다
2. 표와 단계 목록을 AI에게 보냅니다
3. **AI의 답을 손봅니다** 👇

### 🔧 덮어쓰기 규칙

#### ① 중복 단계 제거

AI가 같은 단계를 두 번 고르면 **뒤에 나온 것을 버립니다.**
'근거' 카드가 두 장 나오는 일이 있었습니다.

#### ② 순서 강제 정렬

AI가 순서를 어떻게 내놓든, 명세에 적힌 순서로 다시 줄 세웁니다.

```
데려오기 → 믿음주기 → 부추기기
```

카드뉴스는 이야기 흐름이 있어서, 순서가 섞이면 말이 안 됩니다.
CTA가 3번째에 나오는 카드뉴스는 있을 수 없습니다.

#### ③ 🔑 가격 카드 강제 삽입

**가장 중요한 안전장치입니다.**

AI가 '가격 & 스펙' 카드를 빠뜨렸는데 데이터에는 가격이 있다면, 코드가 직접 만들어 넣습니다.

```
단계: 가격 & 스펙
설명: 구성별 정가와 할인율, 공구가를 표로 정리
```

**공구 카드뉴스에서 가격표가 빠지는 건 있을 수 없기 때문입니다.**
할인 정보를 보러 온 사람에게 가격을 안 보여주면 카드뉴스의 목적이 사라집니다.

#### ④ 최대 장수 자르기

10장을 넘으면 뒤를 잘라냅니다.

### 오류 처리

| 상황 | 결과 |
|---|---|
| API 키가 없음 | "OPENAI_API_KEY가 설정되지 않았습니다. back/.env에 키를 넣어주세요." |
| JSON 구조를 못 읽음 | "읽을 수 있는 데이터가 없습니다. JSON 구조를 확인해주세요." |
| AI 호출 실패 | "카드 구성안 생성에 실패했습니다: (원인)" |

## 5. ② 상세 이미지 검수 (`/cardnews/assets`)

### 하는 일

1. 상세 이미지를 전부 내려받아 크기·비율로 1차 필터 (`assets.py`)
2. 남은 것들의 512px 미리보기를 AI에게 보여주고 판단을 받음
3. **판단 결과를 종류에 따라 다르게 적용합니다** 👇

### 🔧 덮어쓰기 규칙

#### 정지 이미지 — AI가 "쓸 만하다"고 한 것만 남김

정지 이미지는 이미지 생성의 참고 자료로 **자동으로** 쓰입니다.
사람이 확인하지 않으므로, AI가 걸러낸 결과를 그대로 따릅니다.

#### 움직이는 이미지 — 걸러내지 않고 전부 남김

움짤은 **사용자가 화면에서 눈으로 보고 직접 고릅니다.**
기계가 미리 걸러버리면 사용자가 선택할 기회조차 없어집니다.

AI가 "쓸 수 없다"고 판단했더라도 목록에는 그대로 올립니다. 다만 AI가 붙인 장면 설명과 "어울리는 단계" 정보는 함께 남겨서, 나중에 자리를 정할 때 활용합니다.

## 6. ③ 문구 + 디자인 만들기 (`/cardnews/draft`)

### 하는 일

1. 구성안이 지목한 경로의 실제 값을 뽑습니다
2. 사진 카탈로그를 준비합니다 (아래 참고)
3. AI에게 카드 전체를 한 번에 쓰게 합니다
4. **답을 손봅니다** 👇

### 🔧 덮어쓰기 규칙

#### ① 사진 카탈로그를 매번 무작위로 섞습니다

```
후보가 8개를 넘으면 → 무작위로 8개만 뽑음
그리고 순서도 섞음  (번호는 그대로 유지)
```

**왜?** 후보를 전부, 그것도 늘 같은 순서로 보여주면 **AI가 매번 같은 것만 고릅니다.**
다시 생성해도 결과가 똑같아서 "다시 뽑기"의 의미가 없어집니다.

매번 다른 묶음을 다른 순서로 보여줘서 결과가 갈리게 만듭니다.

#### ② 단계 이름은 구성안 것을 씁니다

AI가 답한 단계 이름을 믿지 않고, **순서대로 짝지어** 구성안의 이름을 붙입니다.
AI가 카드 하나를 빠뜨리면 뒤의 카드들이 한 칸씩 밀려서 전혀 다른 카드가 되기 때문입니다.

#### ③ 같은 사진 중복 사용 금지

두 카드가 같은 사진을 고르면 **뒤쪽 카드의 사진을 뺍니다.**
같은 배경이 두 번 나오면 대충 만든 티가 납니다.

#### ④ 움짤은 첫 장·마지막 장에 못 씀

```
첫 장  = 표지     → 공구 이름이 크게 들어가야 함
마지막 = CTA      → 마감 시각이 크게 들어가야 함
```

움짤 카드는 문구가 이미지 **밖에** 붙기 때문에, 글자를 크게 보여줄 수 없습니다.
가장 중요한 두 장을 그렇게 만들 수는 없습니다.

**자리가 없다고 버리지는 않습니다.** 정지 참조로 돌려서 첫 프레임이 참고 자료가 되게 합니다.

#### ⑤ 움짤은 최대 3장

너무 많으면 카드뉴스 전체의 결이 깨집니다.
사용자가 고른 개수와 3장 중 **작은 쪽**까지만 씁니다.

#### ⑥ 🔑 사용자가 고른 움짤은 반드시 쓰이게 합니다

사용자가 움짤을 골랐는데 AI가 무시하고 안 쓰는 일이 있었습니다.
**고른 의미가 없어지므로**, AI가 빠뜨린 것을 코드가 채워 넣습니다.

자리를 정하는 방식:

```
1. 첫 장과 마지막 장을 뺀 나머지 자리 중에서
2. 아직 움짤이 안 들어간 자리를 찾고
3. ②번 AI 검수가 "이 단계에 어울린다"고 한 자리를 우선
4. 없으면 앞쪽 빈자리에 넣음
```

> 💡 **어느 카드에 넣을지는 AI가 정하는 게 원칙입니다.** 이 로직은 AI가 빠뜨렸을 때만 작동합니다.

#### ⑦ 값 범위 강제

AI가 이상한 값을 답하면 기본값으로 바꿉니다.

| 항목 | 허용 값 | 이상하면 |
|---|---|---|
| 문구 위치 | top / center / bottom | `bottom` |
| 정렬 | left / center | `left` |
| 밝기 | dark / light | `dark` |
| 목록 항목 | 최대 4개 | 4개까지만 남김 |

라벨과 값이 **둘 다 비어 있는** 목록 항목은 버립니다.

## 7. ④ 이미지 만들기 (`/cardnews/image`)

카드 한 장당 한 번씩 호출됩니다. 30~60초가 걸립니다.

### 🔑 참고 사진은 상세컷만 씁니다 — 절대 규칙

```
events[].products[].detail_image_urls
```

**이 경로 하나로 코드에서 고정되어 있습니다.**
프론트엔드가 무엇을 보내든 여기서 덮어씁니다.

**왜?**
상품 대표 이미지(`image_url`)는 상품마다 비슷한 정면 컷입니다.
그것만 보고 그리면 **카드 8장이 전부 비슷한 그림**이 됩니다.

상세 이미지는 브랜드가 실제로 연출해서 찍은 사진이라 장면이 다양하고, 실제 촬영 톤을 따라가게 만듭니다.

### 참고 사진 고르는 순서

```
1. ③번에서 이 카드용으로 고른 사진을 맨 앞에 둠  ← 가장 강하게 따라감
2. 나머지 상세 이미지를 뒤에 붙임 (최대 12개 주소)
3. 앞에서부터 내려받아서 5장이 모이면 중단
```

**맨 앞 사진이 가장 큰 영향을 줍니다.** 프롬프트에도 "첫 번째 사진의 장면과 구도를 기준으로 삼는다"고 적혀 있습니다.

### 다운로드 시 거르는 것

| 기준 | 이유 |
|---|---|
| 20KB 미만 | 배너나 여백용 얇은 띠 이미지 |
| 20MB 초과 | 너무 커서 처리 불가 |
| 열리지 않는 파일 | 손상되었거나 이미지가 아님 |

gif나 움직이는 webp는 **첫 프레임을 뽑아 PNG로 변환**해서 씁니다.

### 두 가지 호출 방식

| 참고 사진 | 사용하는 방식 |
|---|---|
| 있음 | **이미지 편집** — 실제 사진 파일들을 함께 보내서 그 위에 새로 그리게 함 |
| 없음 | **이미지 생성** — 글로 된 설명만으로 처음부터 그림 |

### 🔧 안전 필터 대응 (재시도 로직)

브랜드 상세컷에 **아기 사진** 같은 게 섞여 있으면, 이미지 생성 서비스의 안전 시스템이 결과물을 차단합니다.

이때 그냥 실패시키면 그 카드가 통째로 비어버립니다. 그래서:

```
1차 시도: 참고 사진과 함께 생성
   ↓ 안전 필터에 막힘
2차 시도: 참고 사진 없이 글 설명만으로 생성
   ↓ 또 실패하면
그때 오류 표시
```

> 💡 프롬프트에도 "아기나 아이의 맨살, 기저귀 차림이 드러나는 장면은 만들지 않는다"를 넣어 뒀지만,
> **참고 사진 자체에 들어 있으면 프롬프트로는 막을 수 없어서** 이 재시도가 필요합니다.

### 🔑 표지에만 — 큐레이터 아바타 합성 (`back/avatar.py`)

**AI 는 큐레이터 얼굴을 그릴 수 없습니다.** 실제 인물 사진이라 흉내 내면 다른 사람이 됩니다.
그래서 표지 카드만, **다 만들어진 이미지 위에 코드가 따로 얹습니다.**

#### 아바타 만드는 순서 (디자이너 스펙)

```
1. curator.profile_image_url 에서 사진을 받는다
2. 짧은 변 기준으로 가운데를 정사각형으로 자른다
3. 260 x 260 으로 줄인다
4. 원형으로 오려낸다 (테두리 5px 안쪽 = 반지름 125px)
5. 세로 그라디언트 테두리 5px 를 두른다
     위 rgb(150, 0, 255) 보라 → 아래 rgb(255, 0, 80) 핫핑크
6. 배경이 투명한 260 x 260 PNG
```

색을 바꾸시려면 [`back/avatar.py`](../back/avatar.py) 맨 위의 `GRADIENT_START` / `GRADIENT_END` 두 줄만 고치면 됩니다.

#### 놓이는 자리

**기본은 오른쪽 아래**입니다. 다만 문구도 아래쪽에 모이는 카드에서는 얼굴이 글자를 덮으므로 **그때만 오른쪽 위로 피합니다.**

| 문구 위치 | 아바타 자리 |
|---|---|
| 가운데 (표지는 대부분 여기) | 오른쪽 아래 |
| 위쪽 | 오른쪽 아래 |
| 아래쪽 | **오른쪽 위** (겹침 회피) |

문구 위치는 ③번에서 이미 정해져 넘어오기 때문에, 겹칠지 아닐지를 미리 계산할 수 있습니다.

**모서리에서 24px 띄웁니다** (`AVATAR_MARGIN`). 처음에는 56px 이었는데, 문구가 카드
가운데로 모이다 보니 표지 마지막 줄 끝이 아바타에 가려지는 일이 있었습니다.
모서리에 바짝 붙일수록 글자와 멀어져서 24px 로 좁혔습니다.

> ⚠️ 문구가 어디서 줄바꿈되고 어디서 끝날지는 이미지 모델이 정합니다. 마지막 줄이
> 아주 길면 여전히 닿을 수 있습니다. 그때는 이 값을 더 줄이거나 아바타를 작게 만듭니다.

#### 그리기 전에 자리를 비웁니다

이미지를 만들기 **전에** 프로필 사진을 먼저 받아 봅니다. 사진이 있을 때만 프롬프트에 이 문장이 붙습니다.

```
- 오른쪽 아래 모서리의 정사각형 영역(카드 너비의 1/4 정도)은 비워 둔다.
  그 자리에 나중에 동그란 인물 사진이 얹힌다.
```

**순서가 중요합니다.** 아바타가 안 올라올 걸 모른 채 자리만 비우면, 표지 한쪽이 이유 없이 텅 빈 카드가 나옵니다.

#### 아바타가 없어도 카드는 나옵니다

| 상황 | 결과 |
|---|---|
| 프로필 URL 이 없거나 빈 값 | 아바타 없이 평소 표지 |
| 다운로드 실패 (404, 15초 초과) | 아바타 없이 평소 표지 |
| 받은 파일이 이미지가 아님 | 아바타 없이 평소 표지 |
| 합성 중 오류 | **카드는 살리고 아바타만 빠짐** |

어느 경우에도 표지 생성이 실패하지 않습니다. 얼굴 하나 때문에 카드가 통째로 없어지면 안 되기 때문입니다.

> ⚠️ 프롬프트로 자리를 비워 달라고 해도 **AI 가 항상 지키지는 않습니다.**
> 제품이 그 자리에 걸치면 아바타가 살짝 덮을 수 있습니다.

> 💡 표지 카드는 프로필 사진을 받는 동안 생성이 늦게 시작됩니다. 최대 15초입니다.
> 다른 카드에는 영향이 없습니다.

## 8. 화면 쪽에서 하는 일 (`front/src/app/page.tsx`)

### 파일 업로드

- `.json` 확장자가 아니면 파일을 읽지도 않고 거부합니다
  *(파일 선택창의 필터는 끌어다 놓기를 막지 못하기 때문에 따로 확인합니다)*
- 파일이 손상돼서 못 읽으면, 이미 올려둔 데이터는 그대로 두고 실패만 알립니다
- **`events`가 비어 있거나 배열이 아니면** 거기서 끊습니다
  *(공구가 하나도 없으면 뒤 단계가 전부 빈손이 되기 때문입니다)*

### 🔑 공구 선택 (`front/src/lib/events.ts`)

한 파일에 공구가 여러 건(최대 5건) 들어옵니다. 카드뉴스는 공구 한 건 기준이라 하나를 골라야 합니다.

```
업로드된 JSON
   ↓  events[] 를 훑어서 목록을 만든다
공구 목록  ─ 공구명(event_name) + 상품 수
   ↓  사용자가 하나 고른다
{ …나머지는 그대로, events: [고른 것 하나] }
   ↓
서버로 전송
```

**서버는 이 변화를 모릅니다.** 고른 공구 하나만 남긴 JSON은 서버 입장에서 그냥 `events`가 한 건인 평소 데이터입니다. `events[].products[].name` 같은 경로 표기도 그대로 동작합니다. 그래서 **백엔드는 손댈 것이 없습니다.**

| 상황 | 화면 동작 |
|---|---|
| 공구 **1건** | 고를 것이 없으므로 선택 화면을 건너뛰고 바로 분석 시작 |
| 공구 **2건 이상** | 선택 화면을 띄우고 **고를 때까지 AI를 부르지 않습니다** |
| `event_name`이 비어 있음 | "이름 없는 공구 2"처럼 자리 번호로 대신 표시 (고르는 것 자체는 막지 않음) |
| 공구를 다시 고름 | 구성안·움짤 후보·만든 카드를 **모두 버리고** 새로 시작 |

> 💡 **6건 이상 들어와도 막지 않습니다.** "최대 5건"은 데이터 약속이지 화면에서 걸러야 할 조건은 아니라고 보고, 들어온 만큼 전부 보여줍니다.

> 💡 추가 인스트럭션에 적은 내용은 공구를 바꿔도 지워지지 않습니다. 대부분 공구와 상관없는 전반적인 지시라서 그대로 둡니다.

### 늦게 온 응답이 화면을 덮어쓰지 않게

파일을 다시 올리거나 공구를 빠르게 바꾸면, **먼저 보낸 요청의 늦은 응답이 최신 결과를 덮어쓸 수 있습니다.**
그래서 요청마다 번호를 붙여서, 최신 번호가 아니면 결과를 버립니다.

번호는 **구성안과 이미지 검수가 따로** 셉니다. 구성안만 "다시 시도"를 눌렀을 때 아직 돌아오지 않은 이미지 검수 결과까지 버려지면 안 되기 때문입니다.

### 추가 인스트럭션 입력칸 (`front/src/components/instruction-box.tsx`)

입력칸 아래에 **"무엇을 적을 수 있나요?"** 도움말을 접어 뒀습니다. 펼치면 반영되는 것과 반영되지 않는 것을 예시와 함께 보여줍니다.

**왜 필요한가**: 이 지시는 ③번 문구 생성에만 들어갑니다. 구성안(①)은 이 칸을 채우기 전에 이미 확정되어 있어서 *"리뷰 카드 빼주세요"* 같은 요구는 반영될 수 없습니다. **적는 사람이 그걸 알 방법이 없으면 왜 안 먹는지 모른 채 넘어갑니다.**

| | 내용 |
|---|---|
| ✅ 반영됨 | 말투·톤 / 문장 길이 / 표현 금지 / 크게 보일 값 / 카드 밝기·문구 위치 / **배경·분위기** |
| ❌ 반영 안 됨 | 카드 추가·삭제·순서 / **카드에 쓸 데이터 바꾸기** / 22자 넘는 제목 / 데이터에 없는 내용 / **사람이 나오는 장면** |

**지시문은 ③ 문구와 ④ 이미지 양쪽에 통째로 갑니다.** 나누는 것은 코드가 아니라 각 단계입니다. ③은 "장면 요청은 반영하지 않는다", ④는 "말투 요청은 반영하지 않는다"를 프롬프트로 받습니다.

> ⚠️ **사람·아이 금지는 취향이 아닙니다.** 아이가 등장하는 장면은 이미지 생성 서비스의 안전 시스템에
> 막혀 카드가 통째로 실패합니다. 참고 사진에 아기 사진이 섞였을 때를 대비한 재시도 로직이 있는 이유와 같습니다.

> 💡 예시에는 **언제나 지킬 수 있는 것만** 올려 뒀습니다. *"사용 장면 사진 위주로"* 처럼 데이터에 따라 되다 말다 하는 지시는 일부러 뺐습니다 — 사진 카탈로그는 매번 무작위 8장만 보여줘서, 그 안에 없는 종류는 고를 수 없습니다. 왜 안 됐는지 알 수 없는 예시는 없느니만 못합니다.

> 🔑 **문구를 *어떻게* 쓸지는 바꿀 수 있고, *무엇을* 쓸지는 못 바꿉니다.**
> ③번에 넘어가는 값은 **구성안이 지목한 경로의 것뿐**입니다 ([`cardnews.py`의 `paths`](../back/controller/cardnews.py)).
> 구성안이 성분을 안 골랐으면 *"성분을 강조해주세요"* 라고 적어도 성분 값 자체가 프롬프트에 없습니다.

> ⚠️ 글자 수 제한(500자)이 **화면과 서버 두 곳에** 각각 적혀 있습니다.
> `instruction-box.tsx`의 `MAX_INSTRUCTION`과 `prompts.py`의 `MAX_INSTRUCTION`을 **같이** 고쳐야 합니다.

### 이미지 생성 진행 방식

```
문구가 먼저 화면에 뜸
   ↓
빈 카드 자리가 깔림 (몇 장인지는 구성안에 이미 정해져 있음)
   ↓
동시에 3장씩 만들면서, 완성되는 대로 한 장씩 채움
```

**왜 3장씩인가?** 한 번에 다 요청하면 API 쪽에서 막힙니다.
하나가 끝나면 바로 다음 것을 시작해서 쉬는 시간이 없게 합니다.

**한 장이 실패해도 나머지는 계속됩니다.** 실패한 카드에만 오류 표시가 뜹니다.

"AI 생성하기" 버튼은 **문구부터 마지막 카드까지 전부 끝날 때까지** 잠긴 채 "AI 카드뉴스 생성중…" 을 보여줍니다. 이미지 만드는 몇 분 동안 버튼이 원래대로 돌아오면 다 끝난 줄 알고 또 누르게 되기 때문입니다.

### 내보내기 — 다 끝나야 열립니다

완성된 카드를 순서대로 파일로 내려받습니다 (`front/src/lib/download.ts`).

```
01-표지.png   02-문제 제기.png   03-해결의 실마리.png …
```

번호를 앞에 붙여야 파일 목록이 카드 순서대로 정렬됩니다.

| 카드 종류 | 받는 형식 | 왜 |
|---|---|---|
| AI 가 만든 카드 | `.png` | 서버가 이미 png 로 돌려줍니다 |
| 움짤 카드 | `.gif` | png 로 바꾸면 움직임이 사라집니다 |

> ⚠️ **움짤 카드는 문구가 파일에 안 들어갑니다.** 화면에서는 이미지 아래에 문구가 붙어 있지만,
> 내려받는 것은 브랜드 원본 gif 뿐입니다. 그 카드만 문구를 따로 얹으셔야 합니다.

**만들어지는 중인 카드가 하나라도 있으면 버튼이 잠깁니다.** 한 장만 완성돼도 열어 두었더니 급하게 눌러 절반만 받아지는 일이 있었습니다.

**단, 실패한 카드는 기다리지 않습니다.** "모두 성공" 을 조건으로 걸면 9장 중 1장이 실패했을 때 나머지 8장을 영영 못 받습니다. 건너뛴 장수는 내보낸 뒤에 알려줍니다.

> 💡 움짤은 브랜드 서버에서 직접 받아 옵니다. 서버가 막으면(CORS) 그 카드만 실패하고 어느 카드인지 알려줍니다. 그때는 우클릭으로 저장하시면 됩니다.

### 움짤 카드

움짤을 쓰는 카드는 이미지 생성을 **아예 건너뜁니다.** 원본을 그대로 쓰기 때문입니다.
그래서 처음부터 완성된 상태로 표시됩니다.
