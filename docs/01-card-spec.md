# `back/card_spec.py` — 카드 단계 명세서

> **한 줄 요약**
> 엑셀 '카드 구성안' 시트를 코드로 옮겨 놓은 파일입니다. 프롬프트가 아니라 **기획서**에 가깝습니다.
> 여기 적힌 내용이 뒤에 나오는 모든 프롬프트에 자동으로 끼워넣어집니다.

---

## 1. 이 파일이 왜 있나요

카드뉴스는 아무 내용이나 자유롭게 만드는 게 아니라, 기획팀이 정한 **10개 단계** 중에서 골라 만듭니다.
이 10개 단계의 정의(무슨 카드인지, 어떤 데이터를 써야 하는지, 뭘 하면 안 되는지)를 원래는 엑셀 시트로 관리했는데, 그걸 그대로 코드에 옮겨 둔 것이 이 파일입니다.

**중요한 점은 이 파일이 "단 하나의 원본"이라는 것입니다.**

- AI에게 보여주는 단계 목록
- AI가 고를 수 있는 단계의 후보 (여기 없는 이름은 아예 못 고르게 막혀 있습니다)
- 카드 정렬 순서
- 각 단계별 이미지 화각

이 모든 게 이 파일 하나를 읽어서 자동으로 만들어집니다.
**시트가 갱신되면 이 파일만 고치면 되고, 다른 파일은 건드릴 필요가 없습니다.**

---

## 2. 단계 하나는 어떻게 생겼나요

단계 하나마다 7가지 정보가 붙어 있습니다.

| 항목 | 뜻 | 예시 (표지 카드) |
|---|---|---|
| **stage** | 단계 이름 | `표지` |
| **group** | 세 그룹 중 어디에 속하는지 | `데려오기` |
| **core** | 엑셀에서 볼드로 표시된 핵심 카드인지 | `참(True)` |
| **required** | **필수 데이터** — 이 카드를 만들 때 반드시 반영해야 하는 값 | 공구명, 큐레이터 닉네임, 큐레이터 프로필 사진, 제품명 |
| **optional** | **활용 가능 데이터** — 참고되었으면 하는 값. 비어 있어도 됨 | 예약구매 여부, 브랜드명, 브랜드 태그라인 등 |
| **purpose** | 이 카드가 무엇을 전달하는 카드인지 | "공구 제품 대표 이미지와 함께 제품, 인플루언서, 가격 할인율 정보와 그 기한 정보를 담는다." |
| **constraint** | 이 카드에서 하면 안 되는 것 | 없음 |

### `required` 와 `optional` 의 차이가 중요합니다

- **required(필수 데이터)가 비어 있으면 → 그 카드는 아예 만들어지지 않습니다.**
  예를 들어 '근거' 카드는 리뷰가 필수인데, 업로드한 공구 데이터에 리뷰가 하나도 없으면 AI가 이 카드를 후보에서 제외합니다. 리뷰 없이 '근거' 카드를 만들면 AI가 없는 리뷰를 지어내게 되기 때문입니다.
- **optional(활용 가능 데이터)은 비어 있어도 괜찮습니다.** 있으면 쓰고, 없으면 안 씁니다.

### 세 그룹은 카드뉴스의 흐름입니다

| 그룹 | 역할 |
|---|---|
| **데려오기** | 도입부로 관심을 환기시킵니다 |
| **믿음주기** | 제품 소구점 + 정성·정량적 근거 + 객관적 가격·스펙으로 신뢰를 만듭니다 |
| **부추기기** | 공구 현황을 보여주며 행동을 유도합니다 |

이 순서는 **코드가 강제로 지킵니다.** AI가 순서를 섞어서 내놓아도 항상 데려오기 → 믿음주기 → 부추기기 순으로 다시 정렬됩니다.

## 3. 10개 단계 전문

### 🟡 데려오기

#### 1. 표지 ⭐ 핵심

- **목적**: 공구 제품 대표 이미지와 함께 제품, 인플루언서, 가격 할인율 정보와 그 기한 정보를 담는다.
- **필수 데이터**: 공구명 / 큐레이터 닉네임 / 큐레이터 프로필 사진 / 제품명
- **활용 가능 데이터**: 예약구매 여부 / 브랜드명 / 브랜드 태그라인 / 브랜드 설명 / 브랜드 키워드
- **제약**: 없음

#### 2. 문제 제기 ⭐ 핵심

- **목적**: 제품이 필요한 문제 상황을 서술한다. **필수 데이터를 지정하지 않았으니 맥락에 맞게 직접 만들어 낸다.**
- **필수 데이터**: 없음
- **활용 가능 데이터**: 셀링포인트 / 큐레이터 피치
- **제약**: 🚫 **브랜드명과 제품명을 노출하지 않는다**

> 💡 필수 데이터가 없는 유일한 핵심 카드입니다. 데이터를 옮겨 적는 카드가 아니라, 공감 가는 상황을 AI가 직접 써야 하는 카드이기 때문입니다.
> 아직 제품이 등장하기 전 단계라 브랜드명·제품명을 쓰지 못하게 막아 두었습니다.

#### 3. 해결의 실마리

- **목적**: 제품의 셀링포인트와 평판 정보를 통해 해결의 실마리를 제시한다. 필수 데이터를 지정하지 않았으니 맥락에 맞게 직접 만들어 낸다.
- **필수 데이터**: 없음
- **활용 가능 데이터**: 셀링포인트 / 큐레이터 피치 / USP / 해시태그(제품·인스타 양쪽) / 네이버 평점 / 네이버 리뷰 수
- **제약**: 🚫 **브랜드명과 제품명을 노출하지 않는다**

### 🔵 믿음주기

#### 4. 문제 분석

- **목적**: 문제 상황을 제품 속성, 인증 같은 더 객관적인 정보를 통해 설명한다.
- **필수 데이터**: 없음
- **활용 가능 데이터**: 셀링포인트 / 큐레이터 피치 / USP / 해시태그 / 네이버 평점 / 네이버 리뷰 수
- **제약**: 없음

#### 5. 해결(제품) ⭐ 핵심

- **목적**: 브랜드와 제품이 본격적으로 등장한다. 셀링포인트와 큐레이터 피치를 적극 활용한다.
- **필수 데이터**: 브랜드명 / 제품명 / 제품 대표 이미지
- **활용 가능 데이터**: 상세 이미지 / 셀링포인트 / 큐레이터 피치
- **제약**: 없음

> 💡 앞의 두 카드가 이름을 감췄다가, 이 카드에서 처음으로 브랜드와 제품이 등장하는 구조입니다.

#### 6. 근거 ⭐ 핵심

- **목적**: 자체 제품 리뷰와 네이버 리뷰를 근거로 삼되, 데이터가 있으면 제품의 특성과 스펙을 활용해 어필한다.
- **필수 데이터**: 리뷰 / 네이버 평점 / 네이버 리뷰 수
- **활용 가능 데이터**: 특징 / 소재 / 인증 / 상세 이미지 / 구조화된 스펙
- **제약**: 없음

#### 7. 인플 코멘트

- **목적**: 데이터가 있으면 인플루언서가 직접 작성한 포스트 문구를 활용해 어필한다.
- **필수 데이터**: 없음
- **활용 가능 데이터**: 인스타 포스트 캡션 / 상세 이미지
- **제약**: 없음

#### 8. 가격 & 스펙 ⭐ 핵심

- **목적**: 데이터가 있으면 제품의 가격과 객관적인 정보 위주로 전달하는 카드로, 팩트 중심으로 어필한다. **구성별로 정가와 할인율, 공구가를 함께 보여준다.**
- **필수 데이터**: 정가 / 공구가 / 타채널 최저가 / 할인율
- **활용 가능 데이터**: 판매 구성명(option1) / 제품명 / 상세 이미지 / 구조화된 스펙
- **제약**: ⚠️ **구조화된 스펙 값은 추론해서 만들어 내지 않는다. 데이터에 있는 값만 쓴다.**

> 💡 `option1`(판매 구성명)은 원래 엑셀 명세에 없었는데 나중에 추가했습니다.
> 가격만 나열하면 "무엇의 가격인지" 알 수 없어서, 구성 이름이 반드시 함께 있어야 하기 때문입니다.
>
> 💡 이 카드는 **없으면 코드가 강제로 만들어 넣습니다.** 공구 카드뉴스에서 가격표가 빠지는 건 있을 수 없기 때문입니다. (자세한 내용은 `05-cardnews-controller.md` 참고)

### 🔴 부추기기

#### 9. 홍보/전파

- **목적**: 알림 신청수와, 데이터가 있으면 공구 가능 최소 수량을 통해 참여와 전파를 유도한다. 인플루언서 정보도 활용해 어필한다.
- **필수 데이터**: 알림 신청 수
- **활용 가능 데이터**: 큐레이터 정보 / 공구 최소 판매 수량
- **제약**: 없음

#### 10. CTA ⭐ 핵심

- **목적**: 공구 마감 시각을 CTA로 사용하며, 필요하면 가격 정보나 셀링포인트를 써서 마지막으로 후킹한다.
- **필수 데이터**: 공구 마감 시각
- **활용 가능 데이터**: 타채널 최저가 / 할인율 / 셀링포인트 / 큐레이터 피치 / USP / 해시태그
- **제약**: 없음

## 4. 카드 장수 규칙

```
최소 6장, 최대 10장
```

⭐ 표시된 **핵심 카드 6개**(표지, 문제 제기, 해결(제품), 근거, 가격 & 스펙, CTA)는 되도록 넣고,
나머지 4개는 **데이터가 받쳐줄 때만** 넣습니다.

즉 데이터가 빈약하면 6장, 풍부하면 최대 10장까지 나옵니다.
**몇 장을 만들지는 사람이 정하지 않고 AI가 데이터를 보고 정합니다.**

## 5. ⚠️ 데이터 이름 표기 주의 (가장 헷갈리는 부분)

엑셀 시트와 실제 JSON 파일은 **데이터 이름이 다릅니다.**

엑셀은 중첩된 구조를 밑줄로 합쳐서 적었는데(`brand_name`), 실제 JSON 파일에는 그런 이름이 없습니다.
그래서 이 파일에는 **엑셀 표기가 아니라 실제 JSON 경로**를 씁니다.

| 엑셀 표기 | 실제 JSON 경로 |
|---|---|
| `curator_nickname` | `events[].curator.nickname` |
| `curator_profile_image_url` | `events[].curator.profile_image_url` |
| `brand_name` | `events[].brand.name` |
| `brand_tagline` | `events[].brand.tagline` |
| `brand_description` | `events[].brand.description` |
| `brand_keyword` | `events[].brand.keyword` |
| `social_post_cpation` *(엑셀 오타)* | `events[].social_posts[].caption` |
| `reservation_add_count` | `events[].reservation.add_count` |
| `spec[]` | `events[].products[].structured_specs` |
| `curator[]` | `events[].curator` *(배열이 아니라 객체 하나입니다)* |
| `name` | `events[].products[].name` *(브랜드명이 아니라 **제품명**입니다)* |
| `hashtags` | 제품·인스타 양쪽 모두 사용 |

### `[]` 표기가 뜻하는 것

`events[].products[].name` 은 "여러 개의 이벤트 안에 있는, 여러 개의 상품 각각의 이름"이라는 뜻입니다.
상품이 15개면 15개 전부를 가리킵니다.

이 표기법은 `inventory.py`가 데이터를 훑을 때 만드는 경로와 **정확히 같아야 합니다.**
표기가 하나라도 어긋나면 "데이터가 없다"고 잘못 판단해서 카드가 통째로 빠집니다.

> 💡 새 데이터를 명세에 추가할 때는, 실제 JSON 파일을 열어서 경로를 확인한 뒤 적어야 합니다.

## 6. 이 파일이 실제로 쓰이는 곳

| 어디서 | 어떻게 쓰이는지 |
|---|---|
| 구성안 프롬프트 | 10개 단계를 목록으로 펼쳐서 AI에게 보여줍니다 (`_render_stages`) |
| 구성안 응답 형식 | 단계 이름 10개를 **선택지로 못박습니다.** 그래서 AI가 없는 단계를 지어낼 수 없습니다 |
| 문구 프롬프트 | 각 카드의 `purpose`(역할)와 `constraint`(제약)를 함께 붙여 보냅니다 |
| 이미지 프롬프트 | `purpose`와 `constraint`를 다시 붙이고, 단계별 화각 지시를 찾아 붙입니다 |
| 이미지 검수 프롬프트 | "이 사진이 어느 단계에 어울리는지" 고를 선택지로 씁니다 |
| 카드 정렬 | 명세에 적힌 순서대로 카드를 다시 줄 세웁니다 |

## 7. 수정 가이드

### 새 카드 단계를 추가하고 싶다면

이 파일의 `CARD_STAGES` 목록에 항목 하나만 추가하면 됩니다.
프롬프트, 응답 형식, 화면 표시, 정렬 순서가 전부 따라옵니다.

**단, 한 가지만 같이 해줘야 합니다** — `prompts.py`의 `SCENE_DIRECTION`(단계별 이미지 화각)에도 새 단계를 추가해야 합니다. 없으면 "상황에 맞는 장면을 고른다"라는 기본값이 쓰이는데, 그러면 그 카드만 다른 카드와 비슷한 그림이 나올 확률이 높습니다.

### 어떤 데이터를 더 쓰게 하고 싶다면

해당 단계의 `optional` 목록에 JSON 경로를 추가합니다.
**필수로 만들 때는 신중해야 합니다.** `required`에 넣으면 그 값이 없는 공구에서는 카드가 통째로 사라집니다.

### 카드 장수를 바꾸고 싶다면

`MIN_CARDS` / `MAX_CARDS` 숫자를 고칩니다. 프롬프트 문장에 자동으로 반영됩니다.
